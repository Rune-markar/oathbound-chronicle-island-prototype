# V3 確率的国家判断・開発者システム

2026-09-08。V3の通常開始・1マス行動・共通月次・現行V6保存へ接続。

## 開き方

起動画面またはゲーム中の「道具」から「開発者システム」を開く。`index.html?developer=1` でも起動前に開ける。起動前の設定は次の新規世界の50年事前史から使用する。プレイ中の「この冒険の次月から適用」は設定をV6に保存し、時計・人物・過去の判断を保持する。既存の現行V6はmodelを補完し、未来の判断から新方式を使う。不明なmodel版は読み込み・上書きを拒否する。

「変数一覧」は人物と全保存モジュール、生成地理・資源の初期基盤、判断設定、共通ルールを階層表示する。変数名・パスで全階層検索し、50件ずつ最後まで確認できる。現在値、作用、コード参照を表示する。生成時の国境と現在の支配国は別であり、現在値はworldSimulation.generatedWorld.regionalDomainsにある。未知の分類は未分類と表示する。描画キャッシュやループ添字など、一時的な実装変数は台帳の対象外。

## 国家の選択

1. 既存の実行条件で候補を作る。共有国境、国力比、戦争・停戦、同盟提案、動員などの制約は確率設定でも解除しない。
2. 五条件（食料・結束・財政・防衛・主権）の行動効果と、その月の自然増減を共有定義で投影する。最小値を候補の生存評価とする。
3. 標準設定では最良候補との最弱値差が2以内の候補を許可。現在の最弱値35未満では差0に限定する。これは最良候補との比較制約であり、全条件の改善・生存を保証するものではない。
4. 許可された候補の点数を温度6のsoftmaxで確率化し、世界シード・試行番号・年月・国家IDのハッシュから抽選する。候補はID順に並べ、候補順・閲覧回数・保存回数に依存させない。
5. 開戦・停戦がプレイヤー承認待ちなら提案を保持し、承認までの防備・戦線維持を区別して記録する。

点数は次の合計。各項の実使用値をfactorsとして保存する。

| 項 | 計算・作用 |
| --- | --- |
| 状況の基礎点 | 既存の候補baseUtility × 0.12。地理・能力・局面による基礎的な利害。 |
| 生存改善 | （予測最弱値−現在最弱値）× survivalWeight（標準3）。 |
| 人口文化 | 六特性と行動タグの積の平均 × 0.42 × cultureWeight（1）。地方人口・制度・歴史・指導者を反映。 |
| 地政学 | （候補の脅威評価＋関係評価）× geopoliticsWeight（1）。歴史的関係も含む。 |
| 経済・利害 | （利益−危険＋財政効果×財政不足度＋食料効果×食料不足度）× economyWeight（1）。 |
| 環境対応 | （自国地方の平均危機圧＋直近月の穀物未充足率）×（食料効果×1.5＋結束効果×0.5）× environmentWeight（1）。 |
| 費用 | −五条件の直接減少量合計 × costWeight（0.15）。 |

設定の型・範囲・標準値・説明の正本は `V3_MODEL_PARAMETERS`。重み0はその点数項を無効にするが、候補の実行条件や状況の基礎点、市場・地形・天候の法則を取り除かない。種族名だけによる行動固定・交易罰は置かない。

`strict` は最弱値最大、低費用、文化適合、IDの順で一つを選ぶ。抽選はせず確率1/0を記録する。旧イベントにselectionがなければ当時の候補確率は診断値として表示し、新方式の確率と混同しない。

## 地方の食料と飢饉

直近完了月の各地方市場から穀物需要、未充足需要、在庫を集計する。備蓄0.75か月以上かつ未充足10%以下なら、翌月のその地方の飢饉圧力目標を20以下へ下げる。圧力は前月74%＋目標26%で移るため、一度の補給で即座にすべてを解消せず、継続補給が回復につながる。別地方の在庫は使わない。市場情報がない地方は国家・地理条件を使い、数値0を既定値55に置き換えない。

国家判断の環境入力も現支配国へ集計した直近の危機・不足を使い、未来の結果は参照しない。国家判断→危機→市場→国家への需給フィードバックという月次順は維持する。

## 比較と再現

「試行比較」は入力中の判断設定で、同じ現在世界の複製を1〜32回、各1〜120か月進める。各回で試行番号を1ずつ増やす。通常プレイと同じ `advanceV3WorldSimulation` をWorkerで実行し、追加の人物移動・売買・統治操作は行わない。比較は保存中の冒険を進めず、中止・閉じる・ページ離脱で終了する。中止済みWorkerの遅れた応答は無視する。開発者画面を開いている間は、本編の裏側の詳細地形生成も一時停止する。

結果に国家指数、未充足率、期間中の戦争・危機数、行動回数と展開識別値を残す。「結果と再現用の開始状態を保存」はreportとrequestをJSONで保存する。Node.js 22で `runV3SimulationTrials(bundle.request)` を呼ぶと、同じコード版で比較結果を再現できる。単なるシードと現在日付だけでは途中状態を復元できないため、開始状態も含める。

## 検証と範囲

- `npm run check`: 850件。各要因の確率効果、4,000抽選の頻度、危機制約、保存反復・一括一致、原本不変、未知版拒否、地域食料と回復、既存の統治・二終局・戦闘・商会を検証。
- `node scripts/audit-v3-probability.mjs`: 最終版の21ケース・2,880世界月を再実行。結果は `reports/2026-09-08-v3-probability-audit.json`。
- デモと改善経緯は `gameplay-reviews/2026-09-08-v3-probability-lab.md`。

概算地方・国家・市場を単位とするゲーム内仮定。全住民の家計や現実の民族の特性を統計推定したモデルではなく、外部ユーザーによる評価調査は未実施。
