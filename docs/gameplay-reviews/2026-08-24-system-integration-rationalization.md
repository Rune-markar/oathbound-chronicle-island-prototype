# 2026-08-24 ゲームシステム規格化・統合レビュー

## 結論

独自化が最も進んでいたのは、V3の時計と月次進行、V2／V3の商会経営、各機能の保存移行、各モジュール内に複製された決定論的ハッシュ、集団戦から戦略世界への戦果返却だった。個々のゲームルールまで一つの巨大システムへまとめるのではなく、全領域が通る契約だけを共通化した。

```text
通常UI / ドメイン行動
  -> ActionResult
  -> V3統合カーネル
     -> GameClock
     -> 月次SystemRegistry
     -> DomainEvent / GameOperation
  -> V4 SaveRegistry
```

## 監査結果と反映内容

| 領域 | 監査時の独自化 | 統合後の正本 |
|---|---|---|
| 時間 | 歩行時間、動的世界、商会、犯罪組織が別々に月を進め得た | `game-clock.js` の誓暦317年4月・30日月・経過分を正本にし、`clockMinutes` は互換投影だけにする |
| 行動結果 | 多くの公開APIがstateだけを返し、経過時間・出来事・作戦を呼出側が個別解釈した | 通常UIの確定境界で `ActionResult` の `state / elapsedMinutes / events / operation / message / advancedSystemIds` に正規化する。時間を自ら進める商会・裏社会はドメイン側から完全な結果を返す |
| 月次進行 | 世界地図、商会、裏社会の各ボタンが相互領域を直接呼んでいた | `SystemRegistry` が依存先と循環を検証して月境界を一回だけ処理する。起点システムの処理済み情報はUIの手書きskipではなく `ActionResult` から受け取る |
| 横断イベント | 世界年代記、犯罪事件、軍務履歴などが別形式だった | `DomainEvent` にID、種別、発生源、時計、関係者、場所、因果、公開範囲、要約を保存し、複数月進行でも発生元の年月をイベント時計へ保持する |
| 継続作業 | 軍務、販路・支店、犯罪作戦の進行状態を画面ごとに組み立てていた | `GameOperation` の共通読取形式へ投影し、元の領域状態は各システムに保持する |
| 保存 | V3本体と加算領域が個別に版判定し、古い時計と世界年月の不一致余地があった | V4 `SaveRegistry` で旧版ごとの段階移行を実行し、全段階成功後だけシステム版を更新する。V3保存V3は破棄せずV4へ移行して新しい側の年月へ揃える |
| 商会 | V3にV2共通商会ルールと似た実装が再展開されていた | `merchant-company-system.js` をルール正本、`v3-merchant-system.js` を生成国家・現在市場・V3人物状態の薄いアダプターにする |
| 集団戦 | V3へ軍功・経験・銀貨は戻るが、進行中の生成戦争の兵力・前線へ戦果が戻らなかった | 軍務を戦争・正面へ結び、戦術結果を両軍兵力、累計損失、士気、正面進捗、戦争イベントへ一度だけ反映する。適用済みIDは表示用96件とは別に永続保存し、正面失効時は別正面を推測しない |
| 決定論 | FNV系ハッシュ、Mulberry32、LCGが多数のファイルに複製されていた | `determinism.js` に集約し、UTF-16／コードポイント／文字反復と除数の既存差を明示して生成結果を維持する |

## 意図して残した独自性

- 個人戦のフィールド内表示と集団戦の20×14戦術盤は、規模と操作目的が違うため統合しない。
- V2は比較アーカイブ、V3は開発正本という入口・画面・保存境界を維持する。共有するのはドメイン計算であり、V2状態をV3保存へ混ぜない。
- 商会、犯罪組織、軍務、世界情勢の固有ルールと固有状態は各モジュールが所有する。共通基盤は時間、結果、イベント、作業一覧、保存版だけを規格化する。
- `GameOperation` は横断表示用の読取モデルであり、領域固有のstateを置換しない。
- 生成地方と既存V2都市経済の全面置換、V2の仕官・昇進・国家運営・終局のV3移植は今回の「基盤統合」とは別課題として残す。

## 再監査で確認した不足と対応

初回統合後の独立確認で、12か月観測の全イベントが最終月の時計で保存されること、保存システム版が実データ移行なしでも最新版へ上書きされること、表示用戦果96件から消えた`battleId`を再適用できること、失効した正面IDが先頭正面へ誤投影されること、月次skipがUI記述へ残っていることを再現した。

- 発生元イベントの`period`から月境界時計を復元し、商会・裏社会の各月次イベントにも境界時計を付与する。
- `SaveRegistry`へ`legacyVersion`と版ごとのmigrationを必須化し、欠落した移行と未来版を拒否する。世界シミュレーションv1→v2では既存戦果から永続適用証跡を構築する。
- `tacticalOutcomeReceipts`へ適用済み`battleId`を期限なく保存し、表示用戦果台帳だけを96件に制限する。失効正面では兵力のみを反映し、前線未反映を戦争イベントへ明記する。
- 商会決算と裏社会潜伏が`advancedSystemIds`を返し、統合カーネルが起点領域を除外する。通常UIは純粋state遷移も確定前に`ActionResult`へ変換する。
- `SystemRegistry`へ依存先検証と循環検出を追加する。

## 判断

共通基盤は、複数月の時系列、実データを伴う保存移行、長期冪等性、失効参照、起点領域の二重月次までを保証条件とする。以後の新システムは、固有stateと固有ルールを保ったまま、登録版・旧版migration・依存先・正規化・必要な月次フックと作業投影を `SystemRegistry` へ追加し、時間を進める行動を処理済み領域付き `ActionResult`、横断通知を発生月付き `DomainEvent` へ接続する。
