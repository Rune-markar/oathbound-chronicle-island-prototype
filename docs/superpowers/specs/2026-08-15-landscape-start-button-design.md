# 横画面開始ボタン設計

> **履歴仕様（2026-08-20に廃止）**：横画面開始ボタンは縦画面専用化に伴い廃止した。現行の縦向き開始ゲートと `portrait` 固定は [スマホ縦向き本編の固定画面設計](./2026-08-20-mobile-portrait-game-shell-design.md) を正本とする。

## 目的

縦画面のユーザーへ端末回転を依頼するのではなく、ゲーム内ボタンを押すとアプリが全画面化と横向き固定を実行する。ブラウザが固定APIに対応しない場合は、手動回転を要求せず、アプリ内に非対応メッセージを表示する。

## 画面

- 縦画面ゲートの見出しは「横画面でゲームを開始」とする。
- 説明は、ボタン操作により全画面表示と横向き固定を開始することを伝える。
- 主ボタンは「横画面で開始」とする。
- 実行失敗時のメッセージ領域をゲート内に設け、ボタンからフォーカスを移さず結果を通知する。
- 「端末を横向きにしてください」「横向きに回転してください」など、ユーザーへ物理回転を依頼する表現は使用しない。

## 実行方式

横画面開始処理をUIイベントから独立した関数へ分離する。関数は次の順に処理する。

1. 全画面表示中でなければ `document.documentElement.requestFullscreen()` を実行する。
2. `screen.orientation.lock("landscape")` を実行する。
3. 両方が成功した場合は成功結果を返す。
4. API非対応または実行拒否の場合は失敗理由を返す。
5. この処理で全画面化した後に横向き固定が失敗した場合は `document.exitFullscreen()` を実行し、全画面状態を戻す。

UIは成功時にエラーを消し、失敗時には「このブラウザでは横画面固定を利用できません」を表示する。例外の技術的詳細はユーザーへ露出しない。

## ファイル境界

- `src/orientation-control.js`: ブラウザAPIの存在確認、全画面化、横向き固定、失敗時の全画面解除を担当する。
- `src/app.js`: ボタンイベントから横画面開始処理を呼び、結果をゲートへ反映する。
- `index.html` / `styles.css`: 新しい文言、状態メッセージ、処理中表示を担当する。
- `tests/orientation-control.test.mjs`: 成功、API非対応、固定拒否後の全画面解除を実動作として検証する。
- `tests/map-visual.test.mjs`: 横画面ゲートが新しい開始導線を公開していることを確認する。

## エラー処理

- 全画面API非対応: 横向き固定処理を開始せず、非対応結果を返す。
- Orientation Lock API非対応: 必要なら開始済みの全画面表示を解除し、非対応結果を返す。
- 全画面化または固定の拒否: 例外を外へ投げず、失敗結果へ正規化する。
- ボタン連打: 実行中はボタンを無効化し、重複要求を防ぐ。

## 検証

- TDDで成功・非対応・固定拒否後の全画面解除を先に失敗させ、最小実装で通す。
- `npm run check` を完走させる。
- Playwrightで縦画面の見出し・ボタン・エラー領域を確認し、横画面ではゲートが非表示になることを確認する。
- `CHANGELOG.md`、READMEの画面方針、Notionの「仕様変更・更新履歴」を同じ変更単位で更新する。

## 対象外

- CSSによる画面全体の90度回転
- API非対応端末での横向き強制
- 既存の横画面用HUD・地図ドロワー構造の再設計
