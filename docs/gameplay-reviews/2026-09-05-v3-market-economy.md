# 2026-09-05 Generation V3 市場経済シミュレーション 実装レビュー

## 結論

V3市場は、地域係数から毎月同じ在庫を作り直す方式ではなくなった。集落ごとの月産、消費、持越在庫、実在街道のNPC物流、戦争・外部危機、プレイヤーと商会の取引を一つの概算市場状態へ接続した。

## 実装範囲

- `src/v3-market-economy.js`: 集落別六商品、月産・消費、在庫繰越、不足価格、街道物流、有限履歴
- `src/merchant-trade.js`: 地域別の需給基礎値とV3世界市場スナップショットによる実売買
- `src/v3-world-simulation.js`: 外部危機後の月次市場更新とworld-simulation v4保存
- `src/v3-system-kernel.js`: 個人・商会取引差分の世界在庫への一回適用、物流イベント接続
- `src/v3-field-system.js`: 当月の実物流を詳細街道上の目的駆動商人へ投影
- `src/v3-app.js`: 在庫、月産、消費、搬入、搬出、不足、価格傾向の表示
- `src/v3-save-system.js`: world-simulation v3からv4への加算移行

## 回帰確認

Node.js 22.23.2で`npm run check`（src 97ファイルの構文確認・791/791テスト）と`npm run remote:check`が成功した。`git diff --check`も成功。GitHub push、公開、NAS反映は今回実施しない。

固定生成世界で二か月を別々に進めた結果が完全一致し、月産・消費が正値、全在庫が0以上収容上限以下、街道物流の発地搬出と着地搬入が一致することを確認した。プレイヤーが穀物を一個仕入れると、V3統合カーネルの確定後に同じ世界市場在庫が一個減り、価格が据え置きまたは上昇し、再描画で二重減算されない。JSON往復と旧world-simulation v3からの復元、実物流と詳細商人の街道ID・商品・数量の一致も回帰化した。

二販路が同じ発地在庫3個を取り合っても輸送総量を3個以内に制限し、逆ざやは損失になる。一括12か月と一か月ずつ12回の市場・商会決算一致、一括買付と即時売却での価格操作利益防止、月次の二重更新防止、小数銀貨の復元も確認した。

## 通常UI検証

- 穀物の表示在庫24・仕入1.9から、6回の一個仕入れで在庫18・仕入2.4へ変化。売却で在庫が増えて価格が低下した。
- 再読込で在庫と積荷は保持されたが、小数銀貨が0になる既存不具合を発見して修正。修正後は売却で得た銀貨1.7、穀物所持4、世界在庫20.2が再読込後も完全一致した。

## 検証境界

市場は概算集落と街道単位であり、住民一人、店舗一軒、荷車一台を逐次追跡しない。海路物流、通貨別為替、信用・先物市場、価格を使った国家政策の再判断は未実装である。商人の詳細シンボルは当月物流の観測投影であり、荷物一便の連続位置追跡ではない。
