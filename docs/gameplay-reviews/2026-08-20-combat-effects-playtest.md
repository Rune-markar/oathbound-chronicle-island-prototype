# 2026-08-20 戦闘エフェクト実プレイレビュー

## 目的

戦術戦闘のログを読まなくても、誰の攻撃・魔法がどこへ届き、命中、外れ、損耗、回復、状態、地形変化のどれが起きたかを盤面上で理解できるようにする。

## 実装

- 戦闘ドメインが各判定の攻撃元、対象、命中、兵損、HP損耗と、魔法ID、中心、範囲、対象別結果、地形変化を構造化イベントとして記録する。
- 表示層は構造化イベントを優先し、旧スナップショットには既存の差分抽出を予備経路として残す。同じ対象への複数命中、外れ、兵数が減らない個人HP損耗も別々に表示する。
- 通常射撃は矢線、白兵・突撃は斬撃と衝撃、炎陣は炎、氷縛は氷晶、治癒は十字光、土壁は石板として、色だけに依存せず識別できる。
- 同じ範囲魔法の全マスを同時に表示し、炎上・凍結・土壁は継続中の盤面マーカーと読み上げ可能なマス名に残す。
- 通常時の操作ロックは最大1.4秒、低モーション時は移動線を生成せず、静的な結果を450ミリ秒表示する。演出層は操作不能で、結果はライブ領域にも通知する。

## 実ブラウザ確認

- 1280×720の開発戦闘を通常UIから開始し、セレナ魔導隊を選択して炎陣、氷縛、治癒、土壁を一つずつ対象指定・実行した。炎と氷はマンハッタン半径1の5マス、治癒は緑金の十字光、土壁は1マスの石板として表示された。
- 同じ判定で発生した長弓隊の射撃は攻撃線と損耗値として表示され、演出中だけ「命令を実行」が無効、終了後に再有効化された。土壁の一時演出が消えた後も地形マーカーは残った。
- 844×390で氷縛を実行し、右ドックを開いた状態でも術者、到達線、5マスの氷晶を盤面側で確認した。文書とbodyの横溢れはいずれも0だった。
- `prefers-reduced-motion: reduce` では移動・到達線が0件、5マスの静的な炎表示は残り、全要素のアニメーション名が `none` になった。450ミリ秒後に演出層と操作ロックが解除された。
- 一連の操作後のブラウザコンソールはエラー0件・警告0件だった。VPSのスクリーンショットでは日本語フォントの一部が欠けるため、文字列と状態はアクセシビリティスナップショットとDOM値でも照合した。

## 自動回帰

`node scripts/check-source.mjs` と、戦果演出、戦術戦闘、戦闘明瞭化UI、行動時計の焦点テストを実行し、33件すべて成功した。対象は外れ、連続命中、個人HP損耗、炎・氷・治癒・土壁、ターンごとのイベント初期化、継続地形セレクタ、低モーション契約を含む。続いて `npm run check` の全592件も成功した。

## 検証境界

術別の見た目を固定条件で比較するため、ブラウザ確認には4術を装備した開発戦闘を使用した。構造化イベントと表示処理は開発戦闘専用ではなく、通常軍務・探索遭遇・個人戦が共有する戦術エンジンに実装している。全12魔法には共通の発動・範囲表示が適用されるが、今回個別の形状を実ブラウザで比較したのは炎陣、氷縛、治癒、土壁である。
