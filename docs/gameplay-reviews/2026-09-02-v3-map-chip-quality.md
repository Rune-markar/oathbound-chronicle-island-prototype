# 2026-09-02 V3マップチップ画質改善レビュー

## 結論

既定入口 `index.html` のGeneration V3で使う1マス地形を再生成し、`assets/generated/v3/field-terrain-atlas-v2.webp` へ接続した。地形IDからアートを引く `src/v3-art.js` と、通行・移動時間・危険・遭遇を決める `src/v3-field-system.js` の責務分離は維持したため、変更対象は表示品質だけである。

## 変更理由と範囲

従来の地形アトラスは1254pxを4分割するため1セルが313.5pxとなり、背景位置の縮小時にセル境界がサブピクセルへ乗っていた。また、写真調の細密テクスチャへCSSの色レイヤーを重ねていたため、13×11フィールドの約40〜70px表示では地形差が細かいノイズへ潰れやすかった。さらにCSS Gridの行数が未指定で、人物スプライトの内在寸法に行高が引かれ、画面上の1マスが約42×62pxの縦長になっていた。

新アトラスは次を満たす。

- 4×4・1536×1536pxの等分WebPで、各セルを384×384pxに固定する。
- 草原、乾燥草地、砂、凍土、雪、深海、浅瀬、森林、沼、田畑、丘、山、火山、街道、河川、遺跡地面の16枠を維持する。
- 写真コラージュではなく、縮小時の色面と輪郭を優先した統一的な手描きファンタジーRPG表現にする。
- CSSのsoft-light色ブレンドを除き、生成した画を直接 `background-size: 400% 400%` で縮小する。
- `--field-columns` と `--field-rows` の双方で13×11を明示し、各行を `minmax(0, 1fr)` にして表示マスを正方形へ戻す。
- 未踏、生成待ち、世界外は情報秘匿状態のため従来どおり画像を表示しない。

地形30種のうち河川・峡谷河川・運河、集落地面などは従来どおり16枠を意味に応じて共有する。地形種、生成世界、移動、戦闘、保存形式は変更していない。

## 生成方法と最終プロンプト

内蔵 `imagegen` を使い、既存地形アトラスを作風・配置の参照画像としてのみ入力した。生成PNGは配信用の正方形WebPへ変換し、4で割り切れる1536pxへ整形した。

> 4×4の正投影地形スプライトシート。行順は、草原／乾燥草地／砂／凍土、雪／深海／浅瀬／針葉樹林、沼／田畑／丘／山、火山地／土の街道／河川／遺跡地面。各セルは等しい正方形でガター・境界線・文字・建物・人物・透かしなし。48〜80pxでも判別できる大きな色面と輪郭を持つ、写実写真ではない高品質な手描きファンタジー戦略RPG用マップチップ。各セルを端まで満たし、過剰な微細ノイズ、斜視、セルをまたぐ影を避ける。

## 検証

- `tests/v3-art.test.mjs` で新アセットの存在、4×4、1セル384px、1536pxが4で割り切れること、全地形IDの対応を固定する。
- `npm run check` でソース94ファイルの構文と全773テストを確認した。
- Chromiumの通常UIを固定シード `map-chip-review` で開いた。1280×720では13×11、可視マス約41.86×41.75px、390×844では13×11、可視マス約30×29.73pxとなり、双方で横溢れ0、console warning/error 0件、新WebPのHTTP 200を確認した。
- デスクトップで方向操作から北へ1マス移動し、人物スプライトがあっても行高が伸びず、同じ地形アトラスを維持することを確認した。縦画面の方向操作は全て44×44pxだった。

## 検証境界

実ブラウザは代表地形が現れる固定シードを使う。16枠すべてを一つの開始地点で同時に表示すること、物理端末GPUごとの補間差、実機タッチは対象外である。生成画像は視覚品質の改善であり、全セルが数学的に完全なシームレスパターンであることまでは自動判定していない。
