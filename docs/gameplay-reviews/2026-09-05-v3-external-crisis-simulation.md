# 2026-09-05 Generation V3 外部危機シミュレーション 実装レビュー

## 結論

洪水、山火事、飢饉、魔族襲撃を、地方ごとの原因と月次圧力を持つ外部危機としてGeneration V3へ接続した。危機は詳細マスへ無作為出現せず、概算世界で発生・進行・終息し、現在地方で活動中のものだけがプレイヤー周辺へ観測シンボルとして現れる。

## 実装範囲

- `src/v3-external-crisis-system.js`: 地方曝露、圧力、段階、危機度、上限、終息、再発猶予、国家・人口・施設・市場への影響
- `src/v3-world-simulation.js`: 50年事前史と通常月次、年代スナップショット、年代記、国家詳細、world-simulation v3保存
- `src/v3-field-system.js`: 現在地方に限定した13×11視界内の危機シンボル投影
- `src/v3-app.js` / `index.html` / `v3.css`: 世界現象パネル、現象地図、現在地、国家詳細、フィールド上の危機表示
- `src/v3-merchant-system.js`: 戦時市場と外部危機市場の合成
- `src/v3-system-kernel.js`: 外部危機の発生・深刻化・回復・終息を横断イベントへ接続
- `src/v3-save-system.js`: world-simulation v2からv3への段階移行

## 因果と密度の確認

固定シード `v3-race-history-600` の50年事前史で、四種すべての発生履歴と終息、現在の活動中危機を確認する。危機は一地方2件、世界12件を上限とし、詳細側では全世界の危機数にかかわらず現在地方の活動中危機だけを視界へ投影する。

単体回帰では高圧力を注入した各種危機が発生し、最長期間後に回復・終息して6か月の再発猶予へ入ることを確認した。別回帰で国家五条件、集落人口、地方施設、穀物・木材・鉄・薬草の価格・在庫へ危機度別の影響が反映されることを確認した。

初回の既定192×120ブラウザ生成では、危機変化のたびに年代地図スナップショットを複製したためlocalStorage上限を超えた。月次の危機出来事は保持したまま、地図スナップショットを年次・国境変動へ戻し、過去年代用危機を表示項目だけへ圧縮した。併せて「1か月進める」の反復で旧「現在」スナップショットが毎月残る既存挙動も、一件へ置換するよう修正した。保存容量の回帰値と通常開始の再確認を最終検証に含める。

## 通常UI検証

既定入口 `index.html` から192×120、7国家、50年事前史を生成した。固定シード `v3-external-crisis-browser` は現在地方のグランツ白峰地方で危機度1の広域山火事が活動中となり、フィールドの発見済みマスへ「炎／1」のシンボルを表示した。画面の方向操作で5歩進んでシンボルへ接触すると、「詳細マスで突然発生したのではなく、地方単位の月次危機が周辺へ投影されている」という原因表示が出て、`pendingEncounter` は `null` のまま戦闘へ移らなかった。

世界地図では現象レイヤー、12件の活動中危機、現在地方の危機、国家詳細の外部危機、危機発生・深刻化を含む年代記を同じ状態から確認した。1280×720と390×844でbody・世界地図・通常ゲームの横溢れは0。縦画面の世界地図で可視だった19ボタンは最小45×44pxで、44px未満は0件だった。console warning/errorは最終セッションで各0件。初期セーブは約3.78MBで成功し、別固定シードを「1か月進める」で36回反復した後も「現在」スナップショットは1件、保存は約4.27MBで、保存エラーは0件だった。確認後にChromiumとlocalhostサーバーを終了した。

Node.js 22.23.2で `npm run check` を実行し、`src` 配下96ファイルの構文検査と781件の全テストが成功した。`npm run remote:check` と `git diff --check` も成功した。

## 検証境界

危機への能動的な救援・復旧・討伐クエストは未実装である。シンボルへの接触は状況観測だけで、危機を即時解決しない。詳細マスごとの水位、延焼、飢餓人口、襲撃部隊を全世界で逐次計算した証明ではない。ブラウザ確認はheadless Chromiumであり、物理スマートフォン実機ではない。
