# V3 冒険画面：発見・目的・成果の実プレイ確認

## 変更の理由とレビュー

「画面が全く面白くない」という指摘を、周囲への興味、次の行動、行動後の手応えの三点で確認した。既定の `index.html` を開き、同じ生成世界を変更前後で比較した。

| 見つかった問題 | 修正 |
| --- | --- |
| 初期の13×11の大半が未踏で、情報窓が地図を覆う | 円形の発見半径を5へ広げ、主人公HUDを外へ配置。PC15×9、モバイル11×9／小画面11×7 |
| マスの絵から、行く目的や報酬が伝わりにくい | 既知の人物・採集物・敵・集落・依頼を用途と報酬付きで案内。人物には目的の説明を使う |
| 地図から次の行動につながりにくい | 地点の強調と、見える道での一歩案内。近接クリック・方向キー・パッドは従来の一歩操作 |
| 草地・街道・集落が単色の市松状に見える | 古い背景指定のCSS詳細度が地形アトラスを上書きしていた。アトラスを優先し、実ブラウザのcomputed styleで確認 |
| 到着、採集、成長、命中がログだけに埋もれる | 実際のHP・経験・銀貨差、取得・到着・勝利・任官を表示。同じ敵のHP差による命中表示を追加 |
| 現在の場所や物語の段階が視覚的に変わらない | 地形に応じた既存の風景画、進行別の目標、人物史の段階と評議の場面画 |
| 調整途中にモバイルの操作が下へ押し出された | 主人公・風景・目標を短くし、短い画面では7行へ変更。自動行動の完了報告は記録を保って閉じられる |
| 選択表示の記号が増える・現在地を押しても反応しない | 記号の二重追加を除去。現在地の集落・見回り地点は現地の仕事へ接続 |
| 任官後も古いカードのスクロール位置が残る | 地位が変わると歩みの先頭へ戻し、新しい目標を表示 |
| 同じ採集物が周辺案内を埋める | 種類・名前ごとの最寄りと別地点数を最初に表示。全地点の展開と折りたたみを確認 |

操作を持つ表示と判断規則を `v3-adventure-ui.js` / `v3-adventure-presentation.js` に分離した。案内からも既存の `movePlayer` と人物史・自動移動を呼び、報酬や時刻を表示層で再適用しない。未知・未生成の敵や採集物を一覧に含めず、既知経路の途中の敵・人物・危機を迂回する。

## 確認範囲と運用

今回の通常ブラウザ検証は新規開始から地方統治、その後の探索・会話・保存を対象とする。帝国／連邦の全進行は既存のドメイン回帰を含む全868件で確認し、今回のブラウザで二経路を再完走したとは扱わない。風景画は地形種別の共通表現で、個々の生成建築の描画ではない。物理スマートフォン、外部プレイヤーの満足度調査、専用巨大敵の戦術盤は未実施。

開始時のmain/originは `b900703368a6d7f8b79e7ba2021b8892447f148a`、clean・ahead 0／behind 0。専用worktreeで実装した。[Notion変更記録](https://app.notion.com/p/3d501092fbe2811b9c1be97a1e633379)、仕様変更履歴、V3仕様、UI仕様、現状台帳へ同じ変更を反映した。main統合コミットと片付けの最終状態はNotion変更記録へ記載する。今回の変更のpush・静的公開・NAS反映は別工程。
