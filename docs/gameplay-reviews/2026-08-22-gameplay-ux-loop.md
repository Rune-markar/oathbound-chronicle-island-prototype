# 2026-08-22 ゲームプレイUX反復レビュー

## 目的と完了条件

通常プレイで「次に何をするか」「どこへ行くか」「選択後に何が起きたか」を追い、説明だけ存在して実処理へ到達しない箇所、保存・月次更新で消える判断、画面と内部状態が食い違う箇所をなくす。

完了条件は次のとおりとした。

1. 新規の個人プレイで、集落、依頼、仲間、探索、報告の次行動が現在状態から一意に分かる。
2. 移動遭遇、月次復帰、国家戦略のまれな分岐でも、表示と保存状態が一致する。
3. デスクトップと縦型スマートフォンで、主要操作が実クリックでき、重大判断はキーボードでも閉じ込められない。
4. 独立レビューで残存P1/P2なし、全回帰成功、コンソール警告・エラー0を満たす。

## 実プレイで見つけた問題と判断

### 依頼と仲間

- 依頼の現在目標がすべてダンジョン前提に寄り、採集・討伐でも仲間集めや無関係なダンジョンを案内することがあった。
- 保存された進捗より、共有依頼側の実進捗が進んでいる場合でも古い数値を表示し得た。
- 同一地方に複数集落があるとき、受注集落ではない窓口へ案内する可能性があった。旧保存の仮想村IDだけは同地方の実在集落へ移行する必要がある。
- 保留した同行者依頼は後日「断る」しか選べず、保留の意味が失われていた。

判断: 依頼種別ごとの次行動、受注地方・受注集落、共有依頼の実進捗を正本とする。旧保存だけを互換解決し、新規依頼の集落境界は緩めない。保留は後から受諾または拒否できる状態として維持する。

### 移動遭遇

- 地方移動中の遭遇をダンジョン戦として案内し、敗北後も移動先へいるように見える経路があった。
- 戦術結果を「戦場確認」経由で閉じると損耗を二重反映し得た。
- 敗北後の治療所ボタンは、出発地点へ巻き戻した後も移動先の集落コンテキストを使う可能性があった。
- 交戦前撤退は実際には出発地点へ戻るのに「入口へ撤退」と表示していた。

判断: 移動遭遇を明示的な旅イベントとして扱う。勝利だけが到着、敗北・引き分け・交戦前撤退は出発地点へ復帰し、すでに支払った時間・物資と戦闘負傷は返さない。結果反映は終了経路にかかわらず一度だけにする。

### 国家判断と月次更新

- プレイヤー国の限定戦・停戦提案・停戦受諾は不可逆判断として保留される一方、画面には「見送る」しかなく承認できなかった。
- 地政、世界戦争、占領抵抗が同月に判断列を更新すると、別系統の未処理判断や戦役提案を消す可能性があった。
- 停戦受諾後に、終了した同じ戦争の古い「侵攻への対応」が判断列へ残り得た。

判断: 承認APIを実戦役・外交関係・世界戦争台帳へ接続する。限定戦では対象地方、限定目的、副将を選び、完全併合は候補にしない。停戦受諾は国境を変更せず関係、生成戦役、重複する世界戦争、関連判断を同時に閉じる。判断列は生産者別に更新し、同月再計算と保存復元でも未処理判断を保持する。

### 復帰報告、アクセシビリティ、地図

- 留守中の年代記と必須都市事件が同時に開くと、見えている年代記ではなく背後の事件へフォーカスとTab循環が向く可能性があった。
- 月次報告と留守中の年代記が自動的に消えると、内容を読み返せなかった。
- 縦型スマートフォンでは、生成集落とダンジョンが近い場合に地方移動チップが地点を覆い、見た目に存在しても押せない箇所があった。

判断: 復帰報告を先に一画面で提示し、閉じた後で必須事件を開く。重大モーダルでは背景を無効化し、Tab循環、Esc終了、起点復帰を共通化する。報告は明示確認まで保持し、通知から再表示可能にする。地点は44px、地方移動は48pxを下限とし、近接する地点は決定的にずらす。

## 実装した変更

- 依頼目的を `clear_dungeon`、`collect_item`、`defeat_enemy` で分岐し、受注地方への帰還、現地探索、仲間候補、受付報告を四段階で表示した。
- 受注と加入を、実在集落・地方・年月を持つ重複しない人物／村年代記へ記録した。
- 移動遭遇へ出発タイルを保存し、敗北・引き分け・交戦前撤退の位置だけを巻き戻す処理を追加した。
- 限定戦、停戦提案、停戦受諾の承認処理とUIを追加し、入力stateの非破壊性、二重開戦、休戦、停戦案、戦争台帳の整合性を検証した。
- 月次判断列を戦役提案、世界戦争、占領抵抗、地政判断ごとに更新し、最大24件の上限内でも戦役提案を保持した。
- 復帰報告、担当選択、必須事件へ共通のフォーカス管理を適用した。
- 村の実行不能操作へ条件理由を表示し、旧式依頼の重複、NPC性格ラベル重複、保留依頼の片側選択を修正した。
- 縦型地図の地点タップ領域と重なり回避を追加した。
